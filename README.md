# dsh-skills

Skills for the [DeepSeek Harness](https://github.com/deepseek-ai) (DSH) coding agent. One top-level directory per skill, each following the Claude/agentskills `SKILL.md` format so it also works in other skill-aware harnesses.

## Skills

### `research-report`

Turns finished **scientific research** or **code/program investigation** into a report a busy human can read: the bottom-line answer first, then a plain-language explanation of the logic of the work, then findings told as **figures and tables** instead of walls of jargon, then limits and next steps.

- Output: a **self-contained offline HTML** file (vendored Mermaid diagrams + ECharts charts inlined — no CDN, opens from `file://`) or a **Markdown** report.
- Language: Chinese or English, following the user.
- Modes: `quick` (500–1500 words), `full` (2000–6000 words), `update` (revise from feedback).
- The skill **records and updates its own lessons** in [`research-report/references/lessons.md`](research-report/references/lessons.md): read before writing, appended after user feedback, periodically distilled into the reference files. Because this repo is under version control, you can see exactly what it learned and when.

## Install

DSH discovers skills at `~/.dsh/skills/<name>/SKILL.md` (user level), `~/.agents/skills/` (shared with other agents), or `<project-git-root>/.dsh/skills/` (project level). This repo keeps each skill at the top level, so register it with a symlink — one source of truth, edits here apply immediately:

```bash
ln -s "/Users/shangguan/Softwares/my_modules/dsh-skills/research-report" ~/.dsh/skills/research-report
```

Then open a new DSH session (the skill catalog is built at session start; DSH also watches skill directories and refreshes on change).

First use per checkout — fetch the pinned chart libraries once:

```bash
bash research-report/scripts/vendor.sh
```

They are already committed under `research-report/assets/vendor/`, so normally nothing to do; `vendor.sh` re-downloads/updates them and records versions + SHA-256.

## Using it

Ask for the report the way you naturally would — "把刚才的调研整理成一份报告"、"write up what we found as an HTML report"、"汇报一下这个 bug 的调查结果" — and the skill is selected from its description. It will ask only what it cannot infer (audience, language, depth, format), build the report from what the session actually observed, then verify with `finalize_report.py` before presenting.

Markdown output mode is the same content without the HTML machinery (Mermaid code fences render on GitHub).

## Repo layout

```
dsh-skills/
├── docs/research/                  # the survey and analysis behind the skill's design
└── research-report/
    ├── SKILL.md                    # entry point: triggers, workflow, iron rules, modes
    ├── references/                 # loaded on demand
    │   ├── report-structure.md     # anatomy, word budgets, self-check (+ .zh-CN edition)
    │   ├── figures-and-tables.md   # chart selection, quality gates, ECharts/Mermaid snippets
    │   ├── writing-style.md        # plain language, number hygiene, bilingual conventions
    │   ├── html-report.md          # single-file HTML machinery and verification
    │   └── lessons.md              # the skill's self-updating memory
    ├── templates/                  # report.html (self-contained skeleton), report.md
    ├── scripts/                    # finalize_report.py (inline + verify), vendor.sh
    ├── assets/vendor/              # pinned ECharts + Mermaid, vendored for offline use
    └── examples/                   # a real report generated by the skill
```
